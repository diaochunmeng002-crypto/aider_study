总备注：这份静态调用链能证明什么，不能证明什么
能证明：
  - CLI、单次消息和标准 GUI 都复用 main 与 Coder 核心。 # 入口一致
  - --debugwait 位于解析、模型和 Coder 初始化之前。 # 启动门控
  - 输入消息、仓库地图和文件内容如何组成模型上下文。 # Prompt 流程
  - 模型回复如何变成编辑、提交、lint、shell 和测试动作。 # 编辑流程
  - provider 网络调用集中在 send_completion 到 litellm。 # 外部集成
不能证明：
  - 无参数时实际选中的模型和 Coder 子类。 # 需运行时配置
  - Streamlit、LiteLLM、GitPython 的内部调用栈。 # 第三方内部
  - OAuth、网络请求和确认提示实际走了哪些分支。 # 需运行时证据
  - 动态插件或模型设置覆盖后的行为。 # 需运行时观察
  - 当前机器能否完整启动 Aider。 # 本地缺少运行依赖
