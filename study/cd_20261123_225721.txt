[2.3 Streamlit GUI / Web Server]
标准启动方式：
  aider --gui
  aider --browser

外层调用链：
  aider.main:main
    -> apply_debugwait
    -> parse and configure
    -> args.gui branch
      -> check_streamlit_install
      -> launch_gui
        -> from streamlit.web import cli
        -> cli.main(["run", aider/gui.py, "--", *cleaned_argv])

运行边界：
  - Streamlit 提供 HTTP + WebSocket Server 和脚本运行环境。
  - Aider 没有自己的 ASGI/WSGI 应用或业务路由表。
  - GUI 页面脚本是 aider/gui.py；它不是另一个编辑引擎。

GUI 内层调用链：
  aider.gui:gui_main
    -> get_coder()
      -> cli_main(return_coder=True)
        -> 再次进入 aider.main:main
          -> 创建实际 Coder
    -> GUI()
      -> st.chat_input
      -> process_chat
        -> coder.run_stream(prompt)
          -> 与 CLI 共用的 Coder 聊天/编辑链

重要结论：
  - 使用 aider --gui 时，--debugwait 在外层 main 执行。
  - 等待发生在 Streamlit Server 启动之前。
  - 外层 main 消费并移除 --debugwait 后，将清理后的 argv 传给 Streamlit。
  - 内层 main 不会重复等待。

[2.5 直接 Streamlit 启动]
方式：
  streamlit run aider/gui.py -- --debugwait 20

特点：
  - 绕过 aider.main 的外层 GUI 分支。
  - Streamlit Server 会先启动，随后脚本调用 get_coder。
  - get_coder 最终调用 cli_main(return_coder=True)，其中的 main 可以消费参数。
  - 因而等待位置晚于正常 aider --gui，且属于非标准开发路径。
  - 不应把等待逻辑直接加到 gui_main 顶部，因为 Streamlit 会重复执行页面脚本，可能造成每次 rerun 都等待。

建议：
  产品调试优先使用 aider --debugwait N --gui，不要直接 streamlit run。


[3. 当前 --debugwait 实现]

公共门控：
  aider/debugwait.py:9
  def apply_debugwait(argv: list[str]) -> list[str]

接入点：
  aider/main.py:452
  def main(...):
      ...
      argv = apply_debugwait(argv)
      report_uncaught_exceptions()
      ...
      parser = get_parser(...)

参数帮助：
  aider/args.py:686
  --debugwait SECONDS

契约：
  - 默认值：0。
  - 支持 --debugwait 20。
  - 支持 --debugwait=20。
  - 支持小数。
  - 拒绝负数、NaN、Infinity、非数字、缺值和重复参数。
  - 正数时打印 PID 到 stderr，并 flush。
  - 只 sleep 一次。
  - 等待结束后打印继续启动。
  - 0 不输出、不等待，保持正常启动行为。

进程行为：
  [debugwait] pid=<PID> waiting <N>s; attach now
  [debugwait] wait complete; continuing

[8. 边界和风险]
  - --debugwait 只等待进程启动，不暂停每个请求或 Streamlit rerun。
  - 对大型等待值，服务健康检查和编排超时应相应放宽。
  - Streamlit 的 HTTP Server 是 GUI 运行时，不是 Aider 面向外部集成的稳定 REST API。
  - 若未来增加 ASGI/WSGI 服务入口，应在新服务启动器的最前面复用 apply_debugwait，而不能假设 Streamlit 或 ASGI 会自动转发参数。
  - GUI 调试附加时应以终端打印的实际 PID 为准，并确认 IDE 附加到运行 Streamlit Server 的 Python 进程。
